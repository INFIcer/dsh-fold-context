# dsh-fold-plugin

按轮折叠 DSH 会话历史：每轮结束时把本轮的思考、工具输出与长回复折成一条检查点消息，原文可凭编号召回，重要消息永不折叠。

它不接管压缩引擎，只降低每轮历史进入上下文的速度。

## 行为

1. 轮结束（`agent/turn-stopping`）时，把本轮从第一条非保留消息到最后一个节点的区间整体替换成一条 `user/message` 检查点消息。
2. 不折：只有真正的用户原话、`fold_pin` 重要消息、上一次的检查点本身；单轮内容少于 `minFoldChars` 也不折。运行时上下文注入（`<system-reminder>`）、调度提醒都算上下文，跟思考与工具输出一起折掉——折掉的内容下一轮会重新注入最新的一份，要旧的就 `fold_recall`。
3. 检查点正文写清折叠了几步、几次工具调用、工具名、回复的开头与结尾，并给出 `fold_recall("f7")` 这类编号；另有一行「· 文件：改过 …；读过 …」记下这一轮碰过哪些文件——改过的要重读，只读过的不必整份重读。
4. 召回是分级的：`fold_recall("f7")` 在原文不超过 `recallDirectChars` 字时直接给全文；更长的先返回分段目录（段号、类型、字数、开头），模型再用 `fold_recall("f7", parts: ["1", "4-6"])` 或 `parts: ["think"]` / `["tools"]` 多选取回。内容召回会累计次数，超过 `recallReminderAfter` 时要求模型用 `fold_pin` 固化结论；只查目录不算。载荷在折叠时就保存整段原文（含最终回复），召回限流只发生在返回时。
5. 只记得关键词时用检索：`fold_recall({query: "lib/web.js"})` 扫全部折叠原文，只回折叠编号、段号与命中片段，不返回原文，也不计召回次数；拿到编号后再 `fold_recall({id: "f5", parts: ["2","4"]})` 取原文。`id` 与 `query` 同时给时，只在这条折叠里筛段。
6. `fold_pin` 追加一条 `【重要·永不折叠】` 消息，永不被折叠。默认不设条数与长度上限：值不值得记交给模型判断，`maxPins` 与 `pinBudgetChars` 只有在显式设成正数时才作为软上限提示，不会拒绝发布。
7. 系统提示词追加一段 `fold-compression`，说明机制与三个工具（`fold_recall`、`fold_pin`、`fold_config`）的用法。
8. 模型可以用 `fold_config` 在会话中查看、修改或重置配置，不用重启。

## 安装

profile 的 `package.json` 里加 link 依赖并把包名加进 `dsh.profile.bundles`：

```json
"dependencies": { "dsh-fold-plugin": "link:E:/dsh-fold-plugin" },
"dsh": { "profile": { "bundles": ["...", "dsh-fold-plugin"] } }
```

重启 DSH 生效。包内 `cordis.patch.yml` 负责把插件插进插件表。

## 配置

配置按「默认值 < profile 里的 `config` < `$DSH_HOME/fold-config.json`」合并，文件里的值最后生效。加载时越界值自动钳制、未知键忽略并写一条 warn，所以写错配置不会让插件起不来。插件写文件时只保存与默认值不同的项：配置文件是覆盖层而不是快照，升级默认值（单价、上限、提示词）能穿透到已经保存过的会话。

| 字段 | 默认 | 范围 | 作用 |
| --- | --- | --- | --- |
| `enabled` | `true` | 布尔 | 总开关，关掉只留工具与提示词 |
| `minFoldChars` | `1200` | 200~200000 | 一轮里思考+工具输出+回复的字符数低于此值不折 |
| `maxNoteChars` | `320` | 80~4000 | 检查点摘要的硬上限 |
| `noteRatio` | `0.1` | 0.02~0.5 | 摘要按原文比例计算：`min(maxNoteChars, max(80, round(原文 * noteRatio)))` |
| `recallReminderAfter` | `3` | 1~50 | 同一段召回超过几次就提醒固化 |
| `recallReminderText` | 内置文案 | ≤2000 字 | 固化提醒，支持 `{count}` 与 `{tool}`；空串表示不提醒 |
| `recallDirectChars` | `8000` | 1000~200000 | 原文不超过这个字数就整段返回，超过则先返回分段目录 |
| `recallIndexPreviewChars` | `100` | 20~500 | 分段目录里每段预览的字数 |
| `maxRecallChars` | `24000` | 1000~200000 | 单次召回返回的原文上限（也用作分段目录与检索结果的字数上限） |
| `searchPreviewChars` | `60` | 20~300 | 关键词检索结果里每段命中片段保留的字数 |
| `maxSearchFolds` | `8` | 1~50 | 关键词检索一次最多列几条折叠（更早的只给数量提示） |
| `maxPinTextChars` | `0` | 0~200000 | 单条重要消息的正文上限，`0` 表示不截断；设成正数只截断、不拒绝 |
| `maxPins` | `0` | 0~100000 | 重要消息条数的软上限，`0` 表示不限制；超了照常发布，只提示 |
| `pinBudgetChars` | `0` | 0~10000000 | 全部重要消息的字符软预算，`0` 表示不限制；超了照常发布，只提示 |
| `systemPromptText` | 内置文案 | ≤20000 字 | 系统提示段，支持 `{{recallTool}}`、`{{pinTool}}`、`{{configTool}}`、`{{ratio}}`；空串表示不注入 |
| `promptOrder` | `300` | -1000~10000 | 系统提示段的排序值，越小越靠前 |
| `foldToolOutputs` | `true` | 布尔 | `false` 时工具输出既不进摘要、也不进召回载荷，也不计入 `minFoldChars` 的体量 |
| `maxFoldsPerTurn` | `8` | 1~32 | 一轮最多折成几段，超出的片段保留原文 |
| `cacheHitRate` | `0.97` | 0~1 | 前缀缓存的真实命中率（DeepSeek 实测约 97%）。只在没有 provider 回报时兜底；有回报时成本模型改用实测值 |
| `priceCacheHitInput` | `0.02` | 0~1000 | 缓存命中输入单价，元 / 百万 token（DeepSeek 空闲时段官方价，高峰是两倍） |
| `priceInput` | `1` | 0~1000 | 输入（未命中缓存）单价，元 / 百万 token（同上） |
| `priceOutput` | `4` | 0~1000 | 输出单价，元 / 百万 token（同上） |

`recallReminderText` 的占位用单花括号，`systemPromptText` 的占位用双花括号，两者互不影响。

运行时用 `fold_config` 改配置：

- `fold_config({ action: "get" })`：返回当前生效配置、配置文件路径与每项取值范围。
- `fold_config({ action: "set", patch: { noteRatio: 0.2 } })`：只接受上表白名单键，逐项校验；通过后写文件并立即生效。非法键或越界值整批拒绝，不会出现「改了一半」。
- `fold_config({ action: "reset" })`：恢复全部默认值并写文件。

手工改 `fold-config.json` 也可以，但要重启 DSH 才生效；想让改动立刻起作用，用 `fold_config`。

## 数据落在哪

- 会话日志：检查点与重要消息都是普通 `user/message`，`source.kind` 分别是 `fold-checkpoint`、`fold-pin`。恢复/分叉照原样重放，不依赖插件在线。
- `$DSH_HOME/fold-store/<会话>.jsonl`：折叠原文、召回次数、重要消息快照。召回靠它，删掉就只能看到检查点的摘要行。
- `$DSH_HOME/dsh-fold-plugin.log`：运行日志。

## 可视化调试

顶栏「折叠」页的「逐轮报告」按钮（`GET /fold-report?session=<会话 id>`）生成一份单文件 HTML，主体是「逐轮历史」：每一大轮收起时只露用户原话与回复开头，展开就是这一轮的全部内容。用来核对折叠到底省了多少、哪几段被召回或固化：

- 概览：折叠后/不折叠的字符与 token 估算、节省率、折叠段数、召回总次数、重要消息条数与占用字符。
- 按轮对比与折叠段明细：每一步的折叠前/后字符、节省、被召回次数、是否已固化。
- 事件时间线：按 `fold` / `recall` / `pin` 记录的 `at` 排序。
- 逐轮历史：按用户消息切成一轮一块，默认收起；`summary` 上是轮次、折叠编号、已折叠/未折叠/插件生效前、步数与字数，以及用户与回复各一行预览。
- 展开后按消息类型铺色块：用户原话（蓝）、上下文注入（灰，再套一层可展开）、检查点摘要（蓝灰，标注这就是模型实际看到的全部内容）、思考（琥珀）、工具调用（靛）、工具结果（橙）、回复（绿）、重要消息（紫）。折叠摘要在「折叠掉的原文」分隔线之后把原文摊开，方便对照。
- 正文不裁剪：系统提示词、用户原话、长工具输出都完整渲染，超长的思考/调用/结果只加滚动框（工具栏「展开长文本」可去掉高度限制）。工具栏另有「展开全部」「收起全部」「只看已折叠的轮次」。

系统提示词按出现时间单独成块、不参与轮次编号也不折叠，标题上标「第 N 版」与相对上一版的 `+add −del`；插件装上之前的历史会标成「插件生效前·未折叠」。在线报告直接回 HTML、不落盘，零外部资源，不联网。

会话 id 由浏览器当前打开的那个会话给出；进程里已经没有这个会话（比如重启前的老会话）时会返回明确原因，不抛错。

### 离线渲染

宿主进程不在时也能出报告（脚本自己解 zstd 多帧日志、重放 surface）：

```
node tools/render-report.mjs <会话 id>
node tools/render-report.mjs <会话 id> --home C:/Users/Administrator/.dsh --out report.html
```

## 顶栏「折叠」页

插件自带客户端 bundle（`client/client.js`，手写 CJS，不需要构建），在会话顶栏注册一个「折叠」Tab（`conversation.view`，order 20）。页面分两个子页：

- **账本**：每 5 秒拉一次同源 `GET /fold-stats?session=<会话 id>`，看 token 收支；另外每 20 秒拉一次 `GET /fold-composition?session=<会话 id>` 单独更新构成图，不跟整份模型视角一起重拉。
  - 顶部是「上下文构成」：折叠后与不折叠两条共用比例尺的堆叠条（以不折叠总量为满格，折叠后按比例缩短，不折叠条上有一道竖线标出保留位置）、八类占比表（系统提示 / 旧版系统提示 / 用户原话 / 思考与回复 / 工具 / 注入 / 折叠摘要 / 重要消息），以及堆叠面积时间线（横轴每格一块历史；面积是当前视角，虚线是另一视角的总量，可切总量与每块增量）。
  - 两张图左右并排（窄屏自动堆叠）：构成图回答「省掉的是哪一类」，趋势图回答「省下的量怎么累积」，并排放才方便对照，也不会被拉成一整条横线。
- **模型视角**：拉 `GET /fold-view?session=<会话 id>`，按轮展示 `session.deriveMessages()` 派生出的真实历史——也就是折叠后模型实际收到的样子；折叠检查点展开可对照被替换掉的原文。
  - 重要消息不再单独汇总，而是按时间顺序贴在它出现的那一轮卡片之后，紫色常显、展开可读全文——汇总会丢掉「什么时候写下的」这条信息。
  - 「系统提示」只算当前生效的那一版（最后一条非空 `system/message`）。宿主换提示词时会在历史里追加新的 `system/message`，但请求只读最后一条，更早的版本留在会话历史里却不会上行；所以它们单列为「旧版系统提示（不计入）」，只作参考，不进合计、不进构成条与趋势图。
- 系统提示词按出现时间就地成块，不进轮次编号；第 1 版展示全文，第 2 版起默认只展示与上一版的差异（`+`/`-` 行、`@@` 段头），另给「查看这一版全文」。
  - 所有卡片默认收起，点开才把正文挂进 DOM，一次展开大量原文也不会卡；这是界面折叠，和插件的上下文折叠无关。

参数表单不在顶栏：它挂在原生「插件」页的 dsh-fold-plugin 组合包页面里（`plugins.bundle.config`，以组合包名为 key），和装了什么插件、开没开启放在一起。那里 `GET/POST /fold-config` 按同一张字段表渲染，保存即热生效，可一键恢复默认。顶栏只放当前会话的数据，改参数属于插件的一次性设置。

账本页显示（收益与成本都以 token 计，金额只作折算参考）：

- 四张卡：折叠收益（省下的 token）、召回成本（召回原文的输入开销）、重要消息成本（每次请求都要重发的部分）、净收益，单位都是 token。
- 每轮收支条形图：中间是零轴，右侧绿条是折叠省下的 token，左侧红条是这一轮召回与重要消息的开销。
- 折叠明细表：编号、轮次、原文字数、摘要字数、省下 token、被召回次数。召回次数偏高的段就该用 `fold_pin` 固化。
- 成本参考（按单价折算）：头部报折叠后 / 不折叠 / 净省的 token；「按类别拆分（估算）」把三档 token 各自乘单价，给出折叠后、不折叠、净省的参考金额；「逐轮请求开销（估算）」把两种历史各重放一遍，给出每轮的净省 token 与实测输入；「实测账单」把 provider 回报的 `cacheRead` / `input + cacheWrite` / 输出三档照抄成金额，那是唯一贴近真实计费的一栏。
- 重要消息不在这页：它们的成本在这页的 KPI 里，正文按时间顺序列在「模型视角」页各轮之后。

估算口径与宿主 token-meter 一致：每 4 字符算 1 token，每个文本块再加 4 token；页脚写明该口径。旧记录缺轮次或大小字段时按字面量估算，并在界面上标记。

### 三档单价与折算参考（不进收益口径）

折叠的收益一律用 token 报，不折算成人民币：同一批 token 换成高峰价就翻倍，真实请求还会被缓存命中率、请求期压缩器和工具定义改写，算出来的金额既无法验证、也不能跨会话比较。

金额只回答另一件事——「这些 token 按当前单价折算是多少」，出现在成本参考的表格与「实测账单」里，方便和 provider 的实际计费对账。

三个单价都以「元 / 百万 token」为单位，在插件设置页（或 `fold_config` 的 `priceCacheHitInput` / `priceInput` / `priceOutput`）里改，默认取 DeepSeek 2026-11 的官方价目表（空闲时段）：命中 `0.02`、未命中 `1`、输出 `4`。高峰时段是这套的两倍，按实际时段改单价即可。

- 历史部分只算输入：折叠前后的差都在「要重发多少历史」上，所以把省下的 token 按输入均价折算，`cacheHitRate` 是其中的命中占比（默认 0.97）。命中率越高，历史越便宜，而 98% 的前缀在真实请求里确实命中缓存——早先把命中率当成「缓存价折扣当量」（0.25）的算法，会把这条前缀按 0 元计，折算值只有真账的三分之一。
- 输出部分两视角相同：同一句回复不管历史折叠与否都要生成一遍，所以输出金额出现在两份参考里、净省为 0。把它单列是为了让参考值与 provider 回报的口径对得上。
- 合计 = 三档金额相加；金额按合计再取整，不逐行取整后相加，避免分位误差。召回与重要消息按它们出现时的字符数折算一次输入开销。

### 成本估算的口径

折叠省的是「每轮都要把历史重发一遍」的成本，所以不能只看上下文末态大小。估算按轮重放：

- 一轮有 `k` 步，前缀被重发 `k` 次；轮内新增内容按平均半步处在上下文中。
- 前缀缓存只认上一次请求里出现过的内容。折叠在轮末改写了历史，所以上一轮的检查点到本轮首请求是**未命中**，不能算进命中前缀。
- 单轮重放量 = `k × 前缀 + 新增 × (k−1)/2`，其中前缀按 `hitRate` 拆成命中与未命中两档；「新增 + 上一轮检查点」按未命中价折算。收益本身只看 token，金额见上一节。
- 拿到过 provider 回报时，成本模型用实测总量反推两个校准系数：`promptScale` 把重放量缩放到真实请求量（请求期压缩器还会收缩上下文），`outputScale` 缩放输出，命中率也改用实测的 `cacheRead / (cacheRead + input)`。系数是算出来的、不是手调的，只由有回报的轮次决定，再套回全部轮次。
- 同一套式子套在「不折叠」的历史上得到对照值，两者相减是净节省。没被折叠的短回合整段仍算新内容，不会虚增节省。

这是估算，不是账单：它量的是会话历史，而真实请求还可能被请求期压缩器（如 billion-context）改写。所以账本把 provider 回报的「实际请求」并排显示，并在 `cost.drift` 里把差额拆成三段：`governedTokens`（归折叠管的部分——插件生效后的历史加当前系统提示，这一份才和实测并排比）、`legacyTokens`（插件生效前那一轮，没人折得动，实测里早被请求期压缩器改写了）、`externalTokens`（实测里剩下的历史外开销：工具定义、请求期摘要）。差得太多就说明上游还有一层在压缩。同一轮被轮内发言切成多组、或折成 f2a / f2b 多段时，成本按轮合并成一行，不重复计费。`fold_recall` 与 `fold_pin` 的开销按召回/发布时的字符数单算，不进这套重放。


逐轮报告与「模型视角」页的数字用同一套公式，但只给折叠产物（检查点、重要消息、被折叠的原文）计价，不含系统提示词与工具定义，所以会比侧栏「上下文」页的当前占用小一截；后者的总量含这两项。侧栏「上下文」页（dsh-context）还把工具调用的名字与参数各算一块，本插件报告同样这么算，因此同一批消息的估算值可以互相对照。

页头右侧的「逐轮报告」按钮新窗口打开 `GET /fold-report?session=<会话 id>`：服务端按当前历史现算同一份逐轮 HTML，不落盘、不用先调工具。会话已不在进程里时返回 404 并说明原因。

`/fold-stats` 只读 `fold-store` 的记录，不需要会话活着；`/fold-report`、`/fold-view` 与 `/fold-composition` 都要读 `session.deriveMessages()`，会话不在进程里就返回 404。这五个路由缺 `session` 参数返回 400，找不到会话返回 404；`/fold-config` 另接受 `POST`（`{patch}` 或 `{reset:true}`），其余路由只接受 `GET`/`HEAD`。宿主没有 `webServer` 时这个 Tab 不会出现，折叠不受影响；宿主没有插件页（缺 `ui-plugin-manager`）时参数表单也无处渲染，`fold_config` 工具照旧可用。

## 和 billion-context 共用

billion-context（本地代理式压缩）与本插件在不同层工作：前者在请求发往模型之前重写历史，不写 DSH 会话日志；后者用 surface 替换把折叠结果落进日志。两者能同时跑，没有谁会把谁弄坏，但要知道这三件事：

1. **「永不折叠」只在本插件这一层成立。** billion-context 会把它的压缩块范围内的所有消息再摘要一遍，包括我们的检查点与 `fold_pin` 重要消息。模型可能看不到某条重要消息的原文，也看不到某轮的折叠编号；`fold_recall("f7")` 仍能凭本地 `fold-store` 按编号取回原文，所以编号别丢（它在检查点正文里）。
2. **每次折叠都改变请求前缀。** billion-context 下一请求会按 resync 全量重发，这是它的账单成本；折叠本身不另外收费。
3. **两边都在缩减历史，收益会重叠。** 账本上的「省下」是本插件这一层的；代理层再省多少，要看 billion-context 自己的统计。

如果确实需要某些结论在代理层之上也常驻，可以把 `fold_pin` 的内容注入系统提示词（`PromptSection.text` 支持函数形态），代价是每次 pin 变化都会让前缀缓存失效一次；v1 没做。

## 已知限制

- 召回文本按会话存在 `$DSH_HOME/fold-store/`：分叉出来的新会话读不到父会话的载荷，召回会返回「找不到」。
- 每次替换都会让请求前缀变化，接在后面的压缩代理（如 billion-context）下一次请求会全量重发一次；这是折叠的固有成本。
- 只折叠插件在线期间观察到的轮次：插件装上之前的历史保持原样。
- 关键词检索只搜 `fold-store` 里的折叠原文：重要消息与用户原话本来就在上下文里，不参与检索；分叉会话同样搜不到父会话的载荷。检索只定位，不判断内容是否已过时——文件改过没有，看摘要里的「· 文件：改过 …」。
